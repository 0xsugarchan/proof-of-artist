# Proof of Artist — Product Spec

## Concept

**Proof of Artist** is an ENS-based status page for Web3 artists.

It proves:

1. who the artist is
2. which wallet/contracts are official
3. how much ETH their art has generated
4. which AI agent represents or explains the artist

This is not a normal portfolio builder. It is a Web3-native artist proof page.

---

## One-liner

Turn an artist's ENS name into a verified status page showing identity, works, collectors, and ETH earned.

---

## Target User

Web3 artists who sell digital art, NFTs, or onchain works and want to show their credibility through wallet-based proof.

Typical user:

- has an ENS name
- has one or more wallets
- has sold or minted art onchain
- uses platforms like Zora, Manifold, Foundation, OpenSea, Farcaster, X, or personal websites
- wants a cleaner way to prove their Web3 artist identity

---

## Core User Need

The artist wants to show:

> I am the real artist, and my art has generated real ETH value.

The page should make this visible without requiring visitors to inspect wallets, marketplaces, or contracts manually.

---

## Problem

Web3 artist identity is fragmented across:

- ENS
- wallet addresses
- NFT marketplaces
- social accounts
- collection contracts
- personal websites
- AI agents or creator tools

Visitors cannot easily know:

- whether the artist is real
- which wallet is official
- which contracts are official
- how much ETH the artist's work generated
- which AI agent belongs to the artist

---

## Solution

Create a page generated from an ENS name.

The page shows:

- verified ENS identity
- official wallet
- official art contracts
- ETH generated by art
- collector count
- featured works
- AI curator agent profile

---

## ENS Role

ENS must be part of the core product, not just display.

Use ENS for:

- resolving artist name to wallet address
- displaying ENS avatar
- displaying primary name
- storing or reading artist metadata through text records
- connecting official AI agent subnames

Example structure:

```txt
sugarchan.eth              = artist identity
curator.sugarchan.eth      = AI curator agent
gallery.sugarchan.eth      = official gallery page
```

Possible ENS text records:

```txt
artist.name
artist.statement
artist.contracts
artist.zora
artist.farcaster
agent.curator
```

---

## AI Agent Role

The AI agent acts as an artist curator.

It should:

- read the artist profile and onchain summary
- explain the artist's work clearly
- generate a short artist statement
- summarize ETH sales and collector activity
- answer questions about the artist

Example agent:

```txt
curator.sugarchan.eth
```

The agent should feel like an official representative of the artist, not a generic chatbot.

---

## MVP Scope

Build only the minimum version needed for a hackathon demo.

### Required Features

1. ENS input
2. Resolve ENS to wallet address
3. Display ENS profile information
4. Artist can add official contract addresses
5. Show ETH generated by selected contracts
6. Show collector count
7. Show featured works
8. Create AI curator agent profile
9. Public artist proof page
10. Simple chat or Q&A with the curator agent

---

## Main Pages

### 1. Home

Purpose:

- explain the product
- input ENS name
- start page generation

### 2. Artist Dashboard

Purpose:

- confirm ENS identity
- add official contracts
- edit artist statement
- configure curator agent

### 3. Public Artist Page

Purpose:

- show verified artist identity
- show ETH generated
- show works and collectors
- show curator agent

### 4. Curator Agent Page

Purpose:

- show agent identity
- explain what the agent does
- allow simple Q&A about the artist

---

## Key Metrics to Display

Use clear labels.

```txt
Art Sales Generated
Collector Count
Featured Works
Top Sale
Official Contracts
```

Avoid confusing labels such as “wallet balance”.

Important distinction:

```txt
Wallet Balance      = ETH currently held
Total Sales         = gross sales volume
Art Sales Generated = ETH value generated by the artist's works
Net Earned          = after fees, gas, splits, royalties
```

For MVP, prioritize `Art Sales Generated` over exact net profit.

---

## Demo Flow

1. User enters ENS name
2. App resolves wallet and profile data
3. User adds official art contract
4. App calculates or displays art sales data
5. App generates public proof page
6. User creates curator agent subname/profile
7. Visitor opens the public page
8. Visitor asks the curator agent about the artist

---

## Non-goals

Do not build these in MVP:

- full marketplace indexer
- perfect royalty accounting
- multi-chain analytics
- advanced trading features
- full website builder
- complicated social network
- token launch system
- NFT minting platform

---

## Design Direction

The UI should feel like:

- artist status page
- verified identity card
- onchain achievement dashboard
- clean gallery

Avoid making it feel like:

- generic Linktree
- normal portfolio template
- financial dashboard only
- NFT marketplace clone

---

## Technical Direction

Suggested stack:

- Next.js
- TypeScript
- Tailwind CSS
- wagmi or viem
- ENS resolution
- optional IPFS or simple database for metadata
- simple AI API for curator responses

For hackathon speed, allow mock data only where real data integration is too slow. Clearly separate mock data from real ENS resolution.

---

## Cursor Instructions

When implementing:

- keep changes minimal
- do not rewrite the whole project
- do not over-engineer
- prioritize the demo flow
- ENS must be used as identity infrastructure
- AI agent must have a clear role
- avoid repeated UI sections
- keep copy short
- keep the UI mobile-first
- use simple components
- avoid adding features outside MVP scope

---

## Final Product Positioning

Proof of Artist is not a portfolio builder.

It is a verified ENS-based artist status page that proves identity and visualizes the ETH value generated by an artist's work.
